# KETUK. — Knowledge, Rumor, and Memory

## Core Principle

Hearing something is not the same as knowing it.

The world may provide:
- observations;
- claims;
- rumors;
- incomplete addresses;
- specialist findings;
- verified evidence.

The Book must preserve those differences.

---

## Book as Inventory

`BUKU LAMA` is a permanent inventory item.

Clicking it shows current knowledge.

It is not:
- a quest list;
- an objective tracker;
- an omniscient encyclopedia.

It records only what the MC has actually encountered.

---

## Rumor States

### DENGAR

A claim from a person or place.

Examples:
- someone named Adi may buy old lenses;
- drivers have heard the name Sentana;
- an address may be connected to Sentana.

A heard rumor may be:
- correct;
- incomplete;
- stale;
- misunderstood.

### TERVERIFIKASI

Evidence has directly confirmed part of the claim.

Examples:
- meeting Adi and selling him a lens verifies that Adi really buys lenses;
- physically visiting an address verifies the address exists, but does **not** prove Sentana lives there;
- seeing the private-auction poster verifies that the Sentana name is attached to that event.

Verification should be narrow.

Do not upgrade more information than the evidence proves.

---

## NPC Memory

NPCs remember items they have already inspected.

Showing the exact same object repeatedly should not replay:
- the same discovery;
- the same specialist reward;
- the same exposition as if it were new.

A repeat interaction can instead produce:
> "Sudah pernah saya lihat. Belum ada tambahan."

This prevents farming information by repeatedly pressing the same button.

---

## Information Sources

Different sources have different authority.

Examples:
- Bu Ratna: social rumor
- terminal driver: uncertain address/context
- Pak Harun: camera/optics
- Bu Sari: metal/material
- Yanto: small mechanisms
- poster/photo: direct textual evidence

A source being confident does not automatically make it correct.

---

## Dead Ends

Dead ends are allowed.

Examples:
- asking the wrong specialist;
- visiting the correct place at the wrong time;
- following an uncertain address;
- bringing an item to someone with no relevant expertise.

A dead end should teach something about:
- the item;
- the person;
- the place;
- timing;
- the network.

It should not simply display "wrong answer."

---

## UI Rule

Never convert hidden knowledge state into:
- green checkmarks for correct rumors;
- quest arrows;
- "correct NPC" markers;
- route names.

The Book may use textual labels:
- DENGAR
- TERVERIFIKASI

because those describe the MC's evidence state, not the correct next step.

## Current Examples

### Adi
Heard:
> Katanya ada orang bernama Adi yang kadang membeli lensa lama.

Verified only after direct transaction.

### Sentana
Heard:
> Nama Sentana beredar di antara drivers / social contacts.

Later evidence can verify:
- the name appears on a private-auction poster;
- the event exists;
- an address exists.

None of those alone proves every claim about Sentana.
